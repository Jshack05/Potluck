# Local subsystem execution specification

This narrows implementation order under the approved full-app coordination plan; it does not reduce full Potluck scope or authorize live financial operation. The founder confirmed that no hosted Supabase project exists and requested local-first development.

1. Establish one API-owned identity and database. Local development credentials use a salted password hash, random revocable session tokens and no verified-email claim. Production requires external identity and PostgreSQL. Test unauthenticated, guessed-resource, restart, expiry and revoked-session paths.
2. Connect Circle → invitation → accepted membership → Bill proposal → individual acceptance → saved Card setup. All commands execute within one transaction with actor-scoped idempotency and immutable audit events. Domain cents allocation is deterministic. Bill contributions do not reveal funding Cards. Test roles and failure rollback.
3. Replace Splitfinder fixture reads with API records. Public projections contain listing/profile facts only. Brand autocomplete returns brands. A request needs a versioned rules declaration; acceptance opens a conversation, and Circle joining remains a new invitation. Housing is saved privately while verification is unavailable. Test cross-user privacy, duplicate messages, blocks, publication gates and explicit handoff.
4. Add lifecycle administration. Revised Bill offers leave old accepted terms in force; stale offers cannot be accepted. Cancellation/end retain history. Circle leave/removal preserves independent resources. Hosting transfer requires target acceptance and does not transfer financial ownership. Card closure is limited to unissued shells without active connected Bills. Connection changes use independent concurrency checks.
5. Reproduce canonical Figma layouts with native controls, source assets, anchored actions, working calendars and distinct layouts. Preserve guest intent. Store nonsensitive per-user drafts and stable keys for uncertain commands; require account entry for persistent actions. Test actual browser/mobile-sized journeys and run native export checks.
6. Ship no financial-adapter simulation as production behavior. Keep bank/program, settlement, credentials, managed spenders and authorization capability gates closed. Record every missing external prerequisite in the capability register. Complete portable domain specifications and implementation only where provider behavior is documented; do not invent decline codes or financial authority.

Target users, promise, Free placement, acquisition, retention and measurement remain those in the master plan. No new paid gates, provider contracts or public launch approval are introduced by this local specification.

Validation: domain and integration tests, migration/restart checks, strict type checks, formatting, mobile lint/tests/export, dependency audits, direct UI journeys and a fresh final review. A failing security/release gate must remain explicitly reported. Rollback is code rollback plus forward SQL corrections, never destruction of retained user/audit records.
