## Findings and recommended next work

1. **High — Design availability and provider implementation are being conflated.** `connect-bank.tsx` has a disabled connection action; `card/[id]/fund.tsx` and `bill/[id]/payment.tsx` stop before actual transfer submission. Preserve server authorization and consent. Restore the existing intended UI with explicit provider-backed states in a later implementation task; do not invent successful funding or treat these placeholders as the approved design.

2. **High — Import is only partially implemented despite existing designs.** `import-bills.tsx` has two source/account steps and explanatory unavailable-build panels. Figma already has detection review and confirmation frames `1052:5014` / `1052:5015`. Reuse those designs when implementing the adapter, selection, confirmation, errors and returns. A new generic import flow is not needed.

3. **High — Authentication recovery designs exist, but current sign-in omits them.** `sign-in.tsx` implements sign-in/create-account form switching and field errors, but contains no reset-password action or verification/recovery states. Both the older Authentication section and newer continuation recovery frames exist. Reconcile which generation is canonical before restoring the missing states. The auth validation repair remains untouched.

4. **Medium — Create Circle has already been recovered; another rebuild would repeat work.** Source and rendered app include the original illustration, people picker, appearance selector and three settings. The app adds bottom navigation absent from `335:506`, and its spacing pushes the anonymous setting below the initial viewport. Confirm the intended shell and scrolling/inset behavior instead of replacing the form.

5. **Medium — Card lifecycle presentation remains incomplete.** `cards.tsx` always shows a Finish setup row for the first returned card. The captured design includes owned and spender cards with distinct activity/access. The current QA card is unissued, so its setup text is truthful. Later provider integration needs lifecycle-dependent rows and role-specific rendering; do not assume the home route alone completes all role screens.

6. **Medium — Settings routes hide missing workflows behind generic dialogs.** Several actions in `settings/[section].tsx` call an unavailable dialog. Existing security, personal details and continuation account designs must be mapped per action. A shared route is appropriate, but it is not evidence that every settings flow is implemented.

7. **Medium — Prototype entry names do not reliably identify flows.** The captured starting-point list repeats “Splitfinder Memberships — approved search” and “Host proposes a contribution increase” across many different states. Use node IDs and actual reactions in the directory. Rename/reorganize only in a separately authorized change; this audit preserves originals.

8. **Medium — Canvas distance makes discovery difficult.** Original page bounds run from x=-960 to x=117560 and y=-1140 to y=57100. A central directory with direct links is warranted. The existing guide covers continuation work, not a complete canonical map of Potluck.

9. **Classification — Transparent overlay states are not missing screens.** Closed/stay/closing frames such as `199:266`, `207:267`, `488:1134` and `488:1396` intentionally render blank/transparent. Do not delete them merely because they look empty.

10. **Classification — Alternate card stack states are not separate app routes.** `547:1625`, `563:1705`, `570:1755`, `570:1824` and `570:1893` represent collapsed/expanded selections. The app already has expansion state. The same care applies to logo/generic variants and actor fixtures.

All destinations in the **captured** 7,211 transition references resolve to the screen inventory or the two known switch components `424:646` and `424:648`. This is not proof that uncaptured reactions or live prototype journeys work. Hidden hotspots and conditional branches are retained; the explorer does not execute them.
